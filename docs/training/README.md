# Open Door Live Field Guide

The crew training booklet — included in a school's onboarding package and
handed to whoever operates the app on match day. Covers the website admin
panel, match-day roles and logistics, the app, per-sport scoring, and
troubleshooting, in that order. Not legal/business material like
`PROJECT_SPEC.md` or the pitch deck — this is the hands-on operating manual,
written to be paged through mid-match if something goes wrong.

## What's here

- **`booklet.html`** — the source of truth. A self-contained page (inline
  SVG icons, no external assets) also published as a Claude Artifact for
  online viewing — see that link in the PR/commit this was introduced in,
  or regenerate a fresh one by publishing this file. Deliberately
  single-theme (a printed-paper look, not light/dark) since the subject is
  a physical booklet.
- **`Open-Door-Live-Field-Guide.pdf`** — a print-ready export of the same
  page, generated by actually opening `booklet.html` in a real browser and
  printing it (see `scripts/render-pdf.js`) rather than converting through
  Word/LibreOffice, which wouldn't understand the custom CSS or icons. This
  is what a school prints for the physical kit.
- **`Open-Door-Live-Getting-Started-Guide.docx`** — the same content and
  visual system (same icons, colors, phone diagram, chips, cards) as an
  editable Word document, for anyone who needs to tweak wording without
  touching HTML/CSS.
- **`scripts/`** — how both of the above were generated from
  `booklet.html`, so the whole booklet can be regenerated after an edit
  rather than hand-maintained in three formats:
  - `render-icons.js` — screenshots each colored icon variant (and the
    landscape phone mockup) out of `booklet.html`'s own hidden SVG
    `<symbol>` defs into `scripts/icons/*.png`, which the docx embeds.
  - `render-pdf.js` — opens `booklet.html` in headless Chromium and prints
    it to `Open-Door-Live-Field-Guide.pdf`, using the page's own
    `@media print` rules.
  - `generate-docx.js` — builds the `.docx` from scratch with the `docx`
    npm package, referencing `scripts/icons/*.png` for every icon and the
    phone mockup.

## Regenerating after an edit to `booklet.html`

```
cd docs/training/scripts
npm install
node render-icons.js   # re-screenshots every icon + the phone mockup
node render-pdf.js     # re-prints booklet.html to the PDF
node generate-docx.js  # rebuilds the docx from the fresh icons
```

Needs a Chromium binary reachable by Playwright (`npx playwright install
chromium` if one isn't already available) — in this project's own Claude
Code environment, Chromium is pre-installed at a fixed path Playwright
finds automatically via `PLAYWRIGHT_BROWSERS_PATH`, no install needed.

Editing `booklet.html`'s color tokens or icon set means re-running all
three steps in order, since the docx and PDF are both derived from it, not
maintained separately.
